# ChatGal 支持范围与已知问题

更新：2026-09-23。当前应用 **0.1.6**（`0.1.6+7`），默认包 **v264**、教学包 **v9**。本页描述当前客户端；端侧引擎的历史实验与设备差异见 `docs/推理引擎.md`。本版（v0.1.5）相对 0.1.4 加了两处：①换场等待期有状态卡（正在做什么 + 真分步进度 + 已等待秒数），顺带把「L2 记的是原文」这件事的原因显示出来；②立绘 agent 提速（agent 走流式、字段一闭合就切表情/给快捷回复，节拍改成锚点，agent 输出量不再等于台词长度）。验证结果见文末。

### 当前交互与回合边界

- 回复未完成时允许输入草稿，只禁用发送，不暂存、不排队、不自动发送下一句。流式首段出现不等于生成结束；完整正文结束（非流式为展示动画结束）时同步记入本轮上下文并启用发送，保存与记忆整理在后台进行。
- 快捷回复仍由立绘 agent 提供，未完成时保持灰态；正文回合完成后不等待 agent 即可发送下一句。旧 agent 在下一轮开始时作废。
- 请求失败时保留正在编辑的草稿；输入框为空时恢复本次发送的原输入；保存失败继续由原有保护阻止下一轮。页面销毁时取消请求并结束展示等待，不留下挂起回调。
- SSE 收到 `[DONE]` 即结束，不等待服务器关闭响应；`<think>` / `</think>` 可跨增量分片，思考内容不进入流式气泡或最终对白。
- 帮助与关于在主页创作区下方，含版本更新、交流群（仅复制）、爱发电、开源仓、隐私、反馈和日志；设置中不再重复提供关于整组。
- 主页轮播先读磁盘缓存再联网。本轮不改变缓存机制；同站点图片仍以文件名缓存，替换图片建议使用新文件名，同名不同路径和仅修改查询参数不能区分缓存。

## 已知问题

1. **API Key 明文**：存于应用私有 `app_settings.json`，未用 Keystore。外发前需处理。
2. **Release 使用 debug 签名**：交付成熟度问题，现有发布仍沿用此配置；后续正式签名方案须考虑已安装版本的覆盖升级，并备份签名材料。本轮未修改签名。
3. **真机性能与手感**：未在指定中端机完成 30 分钟稳定性实测。以下结论均为**代码审查 + 测试**得出，
   不是真机亲眼确认：
   - 画面效果（立绘缩放、背景铺满、过场动画流畅度）
   - 操作手感（键盘弹出、返回手势、事件点击响应）
   - 长期无尽性能（存档文件增长、保存耗时、界面卡顿）
4. **宽屏双栏 / 键盘 inset 细化**：基础可用，未做完整断点矩阵。
5. **自动开场白的数值平衡**：离线路径下开场白会被记为一轮并可能触发结算；
   真实模型是否同样奖励「只听开场不说话」尚未验证。
6. **朗读相关**：合成请求会把你配置的语音服务商的额度算上；缓存只在同一台设备同一份
   设置下命中。多段连读依赖原生播放器的完成回调，**未在真机上确认过连续播放不丢回调**。
7. **导入字体的覆盖面**：只认 `.ttf/.otf/.ttc`；`.ttc` 字体集合只注册第一个可用字体。
   导入字体不含中文字形时中文会回落到系统字体（这是字体本身的问题，不是 bug）。
8. **设置改动的生效时机**：画面/记忆/字体等运行期参数在**进入游戏时读取**，
   游戏中途改设置要等下次进场才生效（设置页已就地标注）。
9. **日志上限是个「保留条数」上限**：改成 200 会立刻丢掉更早的记录（内存与文件一起裁），
   这是有意的；需要长期留存请把上限调大或自行备份日志文件。
10. **内嵌字体会让 APK 变大约 1.5MB**（站酷快乐体）；不用它也不影响其它功能。
11. **预览窗的输入栏高度**：进过一次游戏后取游戏页实测值；从没进过游戏时用示意高度，
    页面里会注明（不同机型的安全区与快捷回复换行会让输入栏高度差几十 px）。
12. **留白调整可负**：调成负数时消息会靠近甚至盖住立绘（这是有意的微调能力）；
    负到极限也只是「贴着屏幕底」，不会把消息推出画面。
13. **默认值的迁移只对「没手动调过」的值生效**：`消息流留白调整` 先后默认过 35 / 60，
    从没拖过滑条的老设置会被归零（新默认）；一旦你拖过一次，之后任何默认值变动都不再动你的值。
14. **设置文件损坏时的行为**：解析失败会保留 `app_settings.json.corrupt` 备份并在启动后提示，
    界面暂时用默认值 —— **备份文件不要手动删**，那是找回供应商/语音配置的唯一线索。
15. **旧档的「玩家交互」标记**：早期记忆摘要没有 `hasPlayerInteraction` 字段，读回时按
    `true`（保守兼容）。是否重定义为「按原文重建」还没有拍板，所以旧档的 L2 过滤口径与
    新档可能不同。
16. **保存失败的处置是「不继续 + 可重试」**，不是事务回滚：失败后世界状态已经改了内存、
    只是没落盘，界面会挡住后续推进并给重试。磁盘持续坏掉时请先修复存储再继续玩；
    若选择「仍然离开」则允许回主页（进度按界面提示丢弃，不会假装保存成功）。
17. **本轮 P1/P2 修复的验证强度**：来自单文件自动化测试 + release 构建通过，
    **没有真机/模拟器**。「仍然离开」的对话框交互、agent 迟到取消后的画面表现、
    本地无 Key 服务的真实调用，仍需设备侧确认。
18. **事件选择题出口是「点选项」而不是「点一下结束」**：写 `choice` 的事件播到最后一屏后，
    屏幕不再响应单击（避免绕过选择题），必须点某个选项才继续。若某个事件的选项排布在窄屏上
    显得挤，属于**未经真机确认**的观感问题。
19. **存档格式换了（schema 3，分区 + 缩进）**：更早版本写出来的存档一律按「打不开」处理
    （不迁移、不改写原文件），启动后它们会以「打不开」的样子留在「包与存档 → 缺失包的存档 /
    该包下面」——看得到、删得掉，但进不去。这是开发阶段的既定前提，但对「跨版本接着玩」是有影响的：
    升级 APK 后旧档需要另开新档。另外存档体积会比紧凑 JSON 大约 +50%（缩进写出的代价，换来的是可读）。
20. **记忆回廊不再显示关键词记忆的内容**：这是有意的（内容只用于「被提到时唤起角色认知」）。
    要核对某个关键词背后到底记了什么，目前只能看存档里的 `world.memory.trees[].events`。
21. **创意工坊站点的可用性**：客户端只负责交给系统浏览器；站点部署、网络连通性及下载可用性需单独验证，不能从入口代码推断站点在线。
22. **旧档里已经攒下的关键词记忆不会被清理**：提取时机改了，但 v257 之前的档里那些条目
    （source 记着「L1→L2 时提取」）仍在，回廊里照旧只显示它们的关键词、量不会再增长。
23. **端侧推理已从本体拆出**：本体通过 OpenAI 兼容端点连接独立引擎。权重下载、加载、GPU/NPU 加速、原生日志与超时兜底不属于当前客户端能力；历史测量数据及待验证项见 `docs/推理引擎.md`，不能作为当前手机端已验证结论。
24. **轮播图片更新**：当前缓存按文件名命中且非空即复用；官网图片换内容时需换文件名。本轮按用户要求保留该实现。
25. **apps 全量测试的 `did not complete` 范围比原先记录更广**：凡是「跑完整 `ChatPage` + 异步保存」
    的文件都可能中招 —— 实测受害者包括 `home_save_jump_test`、`event_choice_ui_test`、
    `locked_save_test`、`chat_expression_persist_test`、`period_transition_test`、
    `event_save_failure_test`、`endless_joint_review_test`（**含本轮没动过的既有文件**）。
    并发默认跑到 129 条、并发 2 跑到 136 条后整批中断；**逐条单跑必过**。不是断言失败，
    根因仍未定位 —— 核验请单文件跑，不要据整批结果下结论。

## 2026-09-23 立绘 agent：去掉「节拍」

真机反馈「对话基本秒回，但立绘和快捷回复很慢」。查下来原因在设计本身：

- 立绘 + 快捷回复是**同一次请求**产出的（用户早先裁定「每轮固定两次请求，不为快捷回复再发第三次」），而这次请求**只能在台词完整后才发出**——它要读台词才选得出表情。所以玩家感到的等待几乎全在这一次请求上。
- 这次请求里最贵的一项叫**节拍**：把整段台词切成几小片、每片标一个情绪/立绘。它要求模型**把整段台词重贴一遍**，于是 agent 的输出量 ≥ 台词长度、耗时也就 ≈ 再生成一遍台词。
- 而**节拍从来没被接线**：`_runTypewriter` 有 `bounds` 参数就是给它用的，但全项目没有一处传过 → 立绘不会在句子中间换，实际只有"最后一拍"生效（≈ 总立绘）。

用户裁定「一次对话变一次立绘就基本够了」，于是：

1. **提示词不再要求切节拍**，只要求「整段台词最合适的一个情绪 + 一张立绘」+「两条玩家视角的短推荐词」，并明确"不要抄台词、不要逐句标注"。
2. agent 的输出量从"约等于台词长度"降到几十个 token → 表情与推荐词都快一个量级。
3. 解析器**仍然容忍**模型主动给节拍（老形态 `text` 与锚点形态 `startsWith` 都还能解析并走"按位置对齐"），只是不再要求；日志里这种情况会写「无节拍（本版 agent 不再切节拍）」，不再误报成"重建失败"。
4. 每轮多一条耗时日志：`立绘 agent 耗时：首字段=…ms 首条快捷回复=…ms 完成=…ms（prompt … 字 / 回包 … 字）`——回包字数明显大于 prompt 篇幅就说明模型又在抄台词。

验证：`gal_ai/test/look_agent_test` **21 条**（提示词不再含节拍字段/不再要求切节拍、字段顺序「总立绘 → 快捷回复」；锚点与老形态的容忍解析仍各自有用例）、`apps/chatgal/test/look_agent_test` **5 条**（新增「本版正常形态：只给总立绘 + 快捷回复」——断言仍每轮两次请求、推荐词用上、台词未被改动、日志出现「无节拍」与耗时行）。应用 analyze 0 error / 0 warning；两包体检 v264 / v9 通过；ARM64 release APK 构建成功。**仍无真机验证**。

## 2026-09-22 换场等待期的状态提示

### 玩家看到的

点「下一阶段」之后到下一幕出现之间，要等两件**设计上必须等**的事：本幕记忆的 L1→L2 提炼（每个在场角色一次请求）与离场结算（一次请求）。以前这一整段屏幕上什么都没有——玩家只看到「点了没反应」。现在画面中上部会出现一张小卡：

```
✨ 正在整理本幕的记忆（戒戒）
   ▓▓▓▓▓▓░░░░░░░░
   第 1/2 步 · 已等待 6 秒
```

- 进度条是**真的分步**（几个角色 + 要不要结算），不是按时间假推进；步数还不知道时干脆不画条，只显示已等待秒数。
- 一到「完成」就收起来；紧接着的 1.7 秒换幕过场仍由原来那层全屏过场负责（两者不重叠）。
- 等待期**没有任何无限动画**（不用转圈）：等待本来就长，无限动画只会让人更焦躁，也让「等它转完」的自动化测试永远结束不了。
- 阈值触发的**高层整理（L2→L3→…）不在这段里**：它走后台、不锁玩家手，所以没有等待提示。

### 顺带修掉的一处「看不见」

模型没给出可用摘要时（**超时**、报错、或输出无法解析），L2 里记的是**原文的确定性拼接**——这是刻意设计：不能因为一次请求失败就丢掉这段对话，更不能卡住换场。但以前这个原因只写给 `dart:developer`，release 包里完全看不到，玩家只会觉得「记忆怎么突然变成一大段原话」。现在这种情况会：

1. 在界面上弹一句「××的本幕记忆没能提炼（请求失败：timeout（full request timeout）），已按原文记下」；
2. 写进设置 → 运行日志（`appLog.w`，跨启动保留）。

所以「L2 是不是超时了」现在可以直接在运行日志里查到；存档 JSON 里那条 L2 的 `source.kind` 也会标成 `l1_to_l2_fallback`（正常提炼是 `l1_to_l2`）。

## 2026-09-22 立绘 agent 提速（流式 + 字段顺序 + 节拍锚点）

表情与快捷回复都由「立绘 agent」这一个请求产出（每轮固定两次请求：聊天 + agent，不为快捷回复再发第三次）。它以前慢在两处，这轮都改了：

1. **agent 也走流式、字段一闭合就先用**（`LookPlanStream`）：JSON 头两个字段是总立绘（`replyExpression` / `replyPortrait`），所以表情/立绘在 agent 刚开始输出时就切；`suggestedReplies` 一闭合，快捷回复立刻可用，不再等最后那段。只认主字段名——段内的 `expressionId` 不会被误当成整条的总立绘；认不出增量就退回「收流后整包解析」，不可能比原来差。
2. **提示词字段顺序固定为「总立绘 → 快捷回复 → 节拍」**：快捷回复只有两个短词，不该排在最大的那段（逐拍标注）后面、陪着它一起等。
3. **节拍改成「锚点」**：模型只给每拍**开头 4~8 个字**（`startsWith`），正文由客户端按原文切（走既有的「按位置对齐」）。agent 的输出量从此不再等于台词长度——那才是它慢的根因（1000 字台词它也要重贴 1000 字）；而且模型根本没机会改动台词，切出来的一定是原文片段。第一个锚点不在台词开头、或锚点在原文里找不到时，照旧整条退回一张立绘。
4. 快捷回复在 agent 回来前**仍然保持灰态**（显示 `…`、不可点）——这是既有裁定，本轮没改。
